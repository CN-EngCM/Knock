# 命令跑完自动关终端

## 目标

终端命令条目（比如 `code .`）点一下就在新终端面板里执行，跑完面板还留着，要手动关。给命令条目加一个选项：勾上后，命令**成功**结束就自动关掉那块终端面板。默认不勾，行为和现在一样。

## 方案

- **怎么知道「跑完了」：让 shell 自己退出。** 命令是敲进交互 shell 里的（`ptyWrite(id, "命令\r")`），没有「命令结束」的事件。做法是在命令后面追加「成功才退出」：PowerShell 写 `; if ($?) { exit }`，其余（cmd、各类 POSIX shell）写 ` && exit`。shell 一退出，主进程发 `exit` 事件，`App.tsx` 里已有的处理会 dispose xterm 并关面板，**不用新增关面板的机制**。
- **失败不关。** 命令返回非 0（或 PowerShell 报错）时 `exit` 不会执行，shell 和面板留着，报错还看得见。这是刻意的：自动关掉就看不到为什么失败了。
- **追加什么文字由主进程说了算。** 各 shell 的写法不同，而「用的是哪个 shell」（含设置里选「自动」时的探测结果）只有主进程知道，所以 `ptySpawn` 的返回里多一个 `exitSuffix`，渲染端只管拼在命令后面。PowerShell 5.1 没有 `&&`，所以不能一律写 `&& exit`。
- **存储：`items` 表新增 `auto_close INTEGER NOT NULL DEFAULT 0`。** 老库用 `PRAGMA` 探测后 `ALTER` 补列，已有条目全是 0。对外字段 `autoClose: boolean`，SQLite 读出来是 0/1，在主进程统一转成布尔再给渲染端。只对终端命令有意义，条目弹窗里只有类型选「终端命令」时才显示这一行，其他类型一律存 0。
- **界面：** 条目弹窗里，类型为「终端命令」时多一行「自动关闭」开关，旁边一句灰字说明「命令成功后关闭终端面板，失败时保留，方便看报错」。

## 放弃的方案

- **无论成败都关（`; exit`）：** 命令失败时面板一闪就没了，用户看不到报错。
- **写个 `$LASTEXITCODE` 之类的更精细判断：** `$?` 对原生程序按退出码、对 cmdlet 按是否报错，已经够用，不另造规则。
- **读终端输出判断命令结束（识别提示符、OSC 133 等）：** 各 shell 提示符不同，要写一堆识别规则，远比追加一句 `exit` 复杂。
- **渲染端自己判断 shell 种类：** 设置里「自动」的探测逻辑在主进程，渲染端复制一份会不同步。
- **把命令的写入也挪到主进程：** 现在是渲染端在 pty 起来后写，改成 spawn 后立刻在主进程写会改变时序，ConPTY 下有丢输入的风险，没必要为这个冒险。
