# 文件树

在普通工作区里加一个文件树：点工具栏上的按钮，从左侧弹出一个浮层，浏览该工作区文件夹里的文件。实施步骤见 [docs/plans/2026-11-06-文件树.md](../plans/2026-11-06-文件树.md)。验收后把还成立的结论并入 `docs/spec/ui.md`，再删掉这两份文档。

## 目标

- 不离开敲敲就能看到工作区文件夹里有什么，并快速打开、定位、复制路径、在此开终端。
- 浮层不挡操作：看一眼就走，不抢停靠区里终端和工具的位置。
- 只读。新建、改名、删除这些交给系统文件管理器。

## 已定的行为

**入口**

- 工作区工具栏最左边加一个文件树按钮（「打开当前文件夹」旁），点一下弹出，再点一下收起，浮层打开时按钮显示按下态。
- 临时工作区没有文件夹，也没有工具栏，所以没有入口。
- 不加快捷键，不进搜索框，不进工具集菜单。

**浮层**

- 从左边弹出，贴着工作区右侧那块的左缘（紧挨左侧栏），顶部从工具栏下沿开始，一直到底，盖在停靠区上。宽度固定 320px，不可拖拽。
- 无遮罩，不拦截下面的操作。点浮层外面、按 Esc、再点入口按钮、切换工作区，都会收起。
- 双击打开文件或目录后浮层不自动收起。
- 打开时焦点进入树；关闭时焦点回到打开前所在的位置（比如正在输入的终端）。
- 顶部有标题栏：左边文件夹名，右边刷新和关闭两个图标按钮。悬停行时用 title 显示完整路径。
- 面板的右边和下边描一条 1px 的工作区标识色线，与停靠区描边同色。**具体样式后面再调。**

**树**

- 单击选中，双击或回车打开：文件用系统默认程序打开，目录是展开或收起。
- 右键菜单：打开、在资源管理器中显示、复制路径；目录再多「在此打开终端」。
- 同层排序：目录在前，文件在后，各自按名称升序，中文按拼音、忽略大小写。
- **不隐藏任何文件**，`.git`、`node_modules` 也照常显示。不解析 `.gitignore`，不做显示隐藏文件的开关。
- 符号链接按它指向的目标类型显示：指向目录的当目录，坏链接当文件，不加特殊标记。
- 图标用 Material Icon Theme（VS Code 里装机量最大的图标主题），文件夹和文件都按名称或扩展名匹配，匹配不上用默认文件图标，展开的文件夹换开口款。

**状态与刷新**

- 本次运行内，每个工作区各记一份自己的展开状态，切换工作区再切回来还在。关闭应用就丢，不跨重启，与「面板每次启动从空开始」的规则一致。
- 每次打开浮层时，重读已展开的那些目录。标题栏有刷新按钮。不做文件监听。

**出错和空**

- 工作区文件夹不存在或读不了：浮层里显示一句提示，下面两个按钮「重试」和「修改文件夹」（复用工作区右键菜单里已有的流程）。
- 某个子目录读失败（比如没权限）：用 Tree 自带的「加载失败 + 重试」行，不弹 toast。
- 工作区文件夹本身是空的：显示一行灰字。展开的子目录读完是空的，只是没有箭头，不另做提示。

## 方案

### 数据：新增一个读目录的接口

新增 `listDir(workspaceId, dir)`，每次只读一层，用户展开某个目录时才去读。

- 主进程按工作区 id 自己去查该工作区的文件夹，渲染端不传也不能传「根目录」。
- **范围校验只做字面检查**：`dir` 解析成绝对路径后，必须等于或位于工作区文件夹之内，否则按 `bad-request` 拒绝。不跟随符号链接去判断真实位置：这只是为了挡住界面传错参数，不当成安全边界，这是单机单用户的本地工具。Windows 上路径比较不分大小写（`path.relative` 自带）。
- 返回 `entries: { name, path, isDir }[]`。`path` 由主进程拼好，渲染端不自己拼，避免 Windows 与 macOS 的分隔符差异。`path` 同时作为树节点 id。
- 用异步读取（`readdir` 的 `withFileTypes`），不堵主进程。符号链接才需要再 `stat` 一次判断目标类型，失败就当文件。
- 不新增错误类别，沿用现有的 `ApiError`：工作区不存在或没有文件夹 → `not-found`；目录不存在 → `missing`；其余读失败（权限等） → `failed`；越界或入参不合法 → `bad-request`。
- 排序放在渲染端，与 `lib/itemOrder.ts` 一样用 `localeCompare("zh-Hans-CN", { sensitivity: "base" })`，主进程只管读。
- 逻辑放新文件 `src/main/server/fileTree.ts`（纯函数风格），`api.ts` 的处理器只做入参校验和查工作区。

打开、定位、复制路径直接用现有的 `openPath`、`revealPath`、剪贴板。`openLocalPath` 打开成功后会调 `hideWindow`，未钉住时窗口随之隐藏，与启动器行为一致，这里沿用。「浮层不自动收起」指的只是浮层本身，不是窗口。

「在此打开终端」现在的 `openInTerminal(item)` 吃的是条目，不吃路径。要从它里面拆出一个只吃路径的函数（文件夹路径 + 可选命令），原函数改成调用它，文件树右键菜单也调用它。

### 组件：全部从上游 GaN.UI 原样复制

- **树**：`tree.tsx`，连带它依赖的 `drag.tsx`、`direction.tsx`、`hooks/use-size-token.ts`。树自带键盘导航、读屏支持、虚拟滚动和「加载失败 + 重试」行。我们不用它的拖拽，但 `drag.tsx` 要 `@dnd-kit/core`，这个包 2026-11-05 才刚随过度设计清理卸掉，现在要重新加回（`devDependencies`，版本与上游一致 `^6.3.1`）。
- **浮层**：`sheet.tsx`。它基于 Radix 的 Dialog，默认模态（带全屏遮罩、拦截下面的操作），与「无遮罩、不拦截」冲突。解法是根组件传 `modal={false}`：Radix 非模态时不渲染遮罩，点外面和 Esc 收起都是自带的。不用改上游文件。
  - **焦点要自己还**：Radix 非模态对话框关闭时只把焦点还给触发器，不还给打开前的元素（这里没有触发器）。所以打开时先记下当前焦点元素，关闭时若焦点落回 body 就还回去；点外面收起时焦点已在用户点的地方，不抢。（最初以为 Radix 会自动还，实测不会，已改。）
- **图标**：`material-icon-theme`（`devDependencies`，只在打开文件树时懒加载）。映射表和图标出自同一个仓库，不会对不上，而且持续更新。具体怎么打进渲染进程（图标文件懒加载，还是整包图标数据）实现时实测后选更简单的。
- 上游文件保持原样，`docs/spec/ui.md` 的同步清单和 `.prettierignore` 要同步更新。

### 状态：树的数据由面板自己管

Tree 的懒加载结果存在它自己内部，没有「刷新」方法，也不会因为预置了展开列表就自动去读子目录。浮层关闭后树组件会被卸载，所以不能指望它记住数据。做法：

- 面板组件常驻在 `App`，按工作区 id 记展开列表（只在内存里）。
- 每次打开或点刷新：面板从根开始，把根和展开列表里的所有目录逐层重读，拼成带 `children` 的节点数据交给 Tree，并用 `key` 让 Tree 重新挂载，清掉它内部的旧缓存。读不到的展开目录（被删了）从展开列表里悄悄去掉。
- 用户新展开的目录仍走 Tree 的 `loadChildren` 按需读取。
- 面板保存当前工作区文件夹，工作区改文件夹后展开列表作废。

### 预读：首次点开不要顿

最初实现里，第一次点开约 335ms，之后每次约 30ms。拆开量：读目录（3015 项）只要约 10ms，差的 300ms 主要是面板代码包第一次才加载并执行（含约 450KB 的图标映射表）。所以预读分两部分：

- **提前挂载**：App 在空闲时把面板挂上（`open=false` 什么都不画），代码包提前加载完。与 DockZone 的闲时预取同一做法。
- **预读第一层**：面板挂上后后台读一次工作区文件夹的第一层，存原始列表（不建节点，避免大目录白白建几千个节点）。第一次点开先用它立刻画出来，同时照常重读，内容有变化才替换。只在没有要还原的展开状态、且不是点刷新时使用。

结果：首次点开约 25ms，之后每次约 20ms。

踩过的坑：预读让数据比浮层先就绪，而浮层内容经 Radix Portal 晚一拍才挂上，原来「数据就绪后聚焦树」的写法就落空了（树还不在 DOM 里）。改成树一挂载就聚焦（回调 ref + 外层 div 的 key）。

### 浮层的定位与「点入口按钮」

- Sheet 默认是 `fixed` 全屏高度、贴窗口左缘，要用 `className` 覆盖成「工具栏下沿起、侧栏右侧起」。具体位置取值与样式后面再调。
- 外点收起会先于入口按钮的点击发生，不处理的话会一收一开地闪。在 `onInteractOutside` 里放过入口按钮，让它只走自己的开关。
- Sheet 自带的右上角关闭按钮不用（`showCloseButton={false}`），改用自己的标题栏。

## 放弃的方案及原因

| 方案 | 为什么放弃 |
| --- | --- |
| 自己手写一棵只读树（参考 `LauncherList`） | 键盘操作、懒加载、滚动都要自己写。用户倾向直接复用上游，不重复造轮子 |
| 自己手写一个绝对定位的浮层 | 同上。`sheet.tsx` 加 `modal={false}` 就能满足行为，不用自己维护 |
| 文件监听（`fs.watch`） | Windows 上递归监听开销大，属于过度设计。打开时重读加刷新按钮够用 |
| 固定隐藏 `.git`、`node_modules` 等 | 用户决定不隐藏。由虚拟滚动兜底大目录 |
| 解析 `.gitignore` | 过度设计 |
| `vscode-icons-js` 加 `@iconify-json/vscode-icons` | 映射表停在 2023-05，新文件类型对不上 |
| 文件图标只用 lucide 的两个通用图标 | 用户明确要 VS Code 那种按类型区分的图标 |
| 模态浮层（带遮罩） | 看一眼就走的场景，遮罩会打断终端里的工作流 |
| 只预读目录、不预载代码包 | 量出来读目录只占约 10ms，首次点开的 300ms 主要是代码包，只预读目录几乎没改善 |
| 展开状态跨重启保存 | 与「面板每次启动从空开始」的既有决策冲突 |

## 第一版明确不做

- 树内搜索（要找文件用已有的 files 工具）
- 拖文件进终端或便签
- 新建、重命名、删除、移动文件
- 文件预览
- 文件监听
- 显示隐藏文件的开关
- 宽度拖拽调整
- 展开状态跨重启保存

## 实测结果

用隔离数据启动真实窗口验证（样例目录含中文名、空目录、3000 个文件的根、5000 个文件的子目录、junction、坏链接）。

- **Tree 内部行为**：按推断成立。预置带 children 的节点加展开列表，已展开的目录直接显示；换 key 重新挂载后照常渲染；虚拟滚动加 max-h-none! 盖掉 320px 上限，树撑满浮层。
- **层级**：Sheet 的 z-50 盖得住 dockview 的浮动窗口（两者交叠处最上层是浮层）。
- **大目录**：展开 5000 项目录 365ms，DOM 里只渲染约 37 行，滚动到底正常。
- **打包体积**：面板是单独的懒加载包，约 695KB（其中图标映射表约 450KB）；1256 个图标 svg 是独立文件，合计约 1.1MB，只有显示到的才被请求，不进 js。
- **窗口隐藏再呼出**：浮层状态属于面板，符合预期。
- **没有实测**：双击文件真正启动系统默认程序（只验证了文件已被删时的失败提示，避免测试时弹出外部程序）；「在文件管理器中显示」和「复制路径」没有实际点（后者会写系统剪贴板）；英文界面只靠类型检查保证文案 key 齐全，没有逐屏看。
