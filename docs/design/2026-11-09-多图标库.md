# 多图标库

## 目标

快捷启动条目的图标，原来只有 Material Icon Theme 一套（文件类型 / 编程向），做网页收藏、做非编程行业的条目时不够用。新增四套，在「选择图标」弹窗里按标签页切换：

| 标签 | 图标库 | 数量 | 色彩 | 授权 |
| --- | --- | --- | --- | --- |
| 文件类型 | Material Icon Theme（原有） | 915 | 彩色 | MIT |
| 品牌 | SVG Logos | 2303（有 -icon 紧凑版的品牌只列它，实列 1780） | 彩色 | CC0 |
| 办公 | Fluent UI 彩色 | 890（只列 24px 款，约 196） | 彩色 | MIT |
| 通用 | Material Design Icons | 7638 | 单色 | Apache-2.0 |
| 工业 | Siemens IX | 1501 | 单色 | MIT |

## 方案

- **数据来源**：npm 包 `@iconify-json/<库>` 的 `icons.json`（图标名 → svg 内容），放 `devDependencies`。四个包合计约 14MB（logos 占 8.5MB），所以用 Vite 的 `import.meta.glob` 懒加载，每个包是独立的 js 块，第一次要用到才载入，不拖慢启动。
- **图标名**：新库的名字带包名前缀，`mdi:home`、`logos:github-icon`；原有库的名字不带前缀，老数据不用迁移。主进程校验正则放宽成「可选前缀 + 原来的名字格式」。
- **显示**：仍然是 `<img>`。svg 在渲染端现拼成 data 地址并缓存，所有现成的显示点（左栏、工具栏、搜索候选、停靠标签、条目弹窗）不用改成别的元素。
- **单色库上色**：`<img>` 里的 svg 吃不到页面的文字色，所以拼 svg 时把颜色直接写进去，取主题前景色；深浅主题用现成的 `light` 参数切换，停靠区焦点标签的「浅色主题里是深色底」规则也自动适用。
- **没载入时**：先给透明占位，载入完经订阅通知（`useSyncExternalStore`）让用到图标的组件重绘。
- **品牌 logo 看不清**：GitHub 这类近黑的 logo 在深色主题里和底色融在一起，按 svg 里写死的颜色算平均亮度，太接近底色就垫一块反色的圆角底。什么颜色都没写的 logo（苹果、OpenAI、X、Vercel 等 188 个）按 SVG 默认填充算纯黑，一样处理。
- **品牌 logo 的字标版**：不少品牌同时有一串文字的字标版（缩到图标大小看不清）和紧凑的 `-icon` 版，有 `-icon` 版的只列它。
- **选择弹窗**：顶上标签页切库；新库只搜英文图标名，多个词要全包含（`arrow right` 能找到 `arrow-right`）；一次最多画 300 个，后面「显示更多」。

## 放弃的方案

- **全部拆成 svg 文件**（和 Material Icon Theme 一样）：一下多出一万两千个文件，安装包文件数暴涨，而且要写拆分脚本。
- **`@iconify/react` 或在线接口**：多引一个运行时依赖，在线接口还要联网，和「单机单用户」相违。
- **单色库用 CSS mask 跟随文字色**：所有 `<img>` 显示点都得改成别的元素，改动面大；烘焙颜色一处就够。
- **虚拟滚动网格**：七千多个图标一次画出来确实重，但「显示更多」几行代码就够用，不加虚拟列表。
- **fluent 全尺寸都列**：199 个图标 × 6 个尺寸，一屏全是长得一样的，只列 24px 一款。
