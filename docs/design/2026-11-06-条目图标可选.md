# 条目图标可选

## 目标

快捷启动条目（左栏、工作区工具栏、搜索候选共用同一个 `KindIcon`）的图标，除了现在的自动匹配，还能由用户从文件树用的 Material Icon Theme 图标包里手选。不选就是「自动」，行为和现在完全一样。

## 方案

- **存储：复用 `items.icon` 列。** 它是旧版「网站图标缓存文件名」的遗留，现在没有任何代码读写，不加列、不迁移。新含义：图标包里的图标名（`iconDefinitions` 的键，如 `pnpm`、`folder-src`）；`NULL` = 自动。库里认不得的值（旧版遗留，或包升级后删了）一律按自动显示，不报错。
- **校验：主进程只查格式**（字母数字和 `_.-`，最长 64）。图标包只在渲染端，主进程不认得图标名，也不该为此把 450KB 的映射表带进来。
- **浅色主题：** 包里 54 个图标另有 `<名>_light` 款，渲染端按主题自动换，库里只存基础名。
- **选择界面：** 条目弹窗里加一行「图标」，点开子对话框（照 `ShortcutPickerDialog` 的做法）：搜索框 + 图标网格 + 「自动」按钮。可选 915 个，去掉 `_light` 款和文件夹展开款（`-open`，展开状态才用）。搜索既匹配图标名，也匹配映射到它的扩展名、文件名、文件夹名，所以搜 `md` 能找到 markdown。
- **显示：** `KindIcon` 先看 `item.icon`，包里有就用，否则走原来的自动规则（网页 / 应用 / 命令各一张固定图，文件按名字匹配）。

## 放弃的方案

- **新加一列 `icon_id`：** 旧列没人用，多一列只会留下两个含义相近的字段。
- **主进程校验图标名是否存在：** 要把映射表打进主进程，得不偿失；渲染端认不得时回退自动已经够用。
- **用 Popover 做选择器：** 套在对话框里要额外处理滚轮和焦点，而项目里已有子对话框的先例。
- **命令按第一个词自动匹配（`pnpm dev` 显示 pnpm）：** 用户选了「手选」，自动规则保持原样，不加新规则。
- **抓网站自己的 favicon：** 要联网，超出本次范围。
