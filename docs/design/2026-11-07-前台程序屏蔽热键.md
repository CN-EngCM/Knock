# 前台程序屏蔽热键

## 目标

玩游戏时手快双击了 Ctrl，敲敲的主窗口弹出来盖在游戏上。要做一份「屏蔽名单」：名单里的程序在最前面时，呼出热键不响应。名单默认为空，空名单等于没开这个功能，行为和现在一样。

## 方案

- **怎么知道前台是谁：新增 `koffi`（Windows 专用）。** Electron 没有「查前台窗口」的接口，热键钩子拿到的也只有键码。`koffi` 能直接调系统接口：`GetForegroundWindow` 取前台窗口 → `GetWindowThreadProcessId` 取进程号 → `OpenProcess` + `QueryFullProcessImageNameW` 取程序路径，最后只留文件名。整条链实测约 0.014 毫秒，不影响呼出速度。`koffi` 3.x 不含原生代码，二进制放在 `@koromix/koffi-<平台>` 分包里，所以打包时 `koffi` 和 `@koromix` 都要放进 `asarUnpack`。
- **平台差异集中在 `server/foreground.ts`。** 只导出一个 `foregroundExeName()`：Windows 返回小写文件名（如 `eldenring.exe`），其他平台直接返回 `null`。`koffi` 用 `createRequire` 在 `try` 里按需加载，加载失败等同于「查不到」，不会让应用启动崩掉。
- **名单怎么匹配：按程序文件名，不分大小写，不看路径。** 存进去之前统一整理：去空白、取路径里最后一段（粘贴了整条路径也行）、转小写、没写 `.exe` 就补上、去重。读出来的永远是整理后的形状，所以匹配时直接 `includes` 即可。
- **只拦「呼出」，不拦「收起」。** 双击修饰键和组合键最终都调用 `app.ts` 的 `toggleWindow`，但托盘点击也调它，而托盘点击是用户主动操作，不该被拦。所以把 `toggleWindow` 的主体抽成 `toggle(summon)`，参数是「呼出动作」：托盘传 `showWindow`，热键传「先看名单再 `showWindow`」。这样窗口已显示时按热键收起照常工作，二次启动唤起、macOS 点 Dock 也都不受影响。
- **查不到就放行。** 查询失败（`koffi` 不可用、受保护进程不让查文件名）一律当作没命中，照常呼出。项目一直守着「呼出永远可用」，宁可偶尔漏拦一次，也不能让热键因为一次查询失败彻底失灵。
- **被拦时完全没反应。** 任何提示（弹层、通知）都会再次盖到游戏上，等于没拦。
- **存储：settings 表新增键 `hotkeyBlockApps`**，值是 JSON 字符串数组，缺省 `[]`。每次呼出现读库，不做缓存，设置页保存后立刻生效，不用通知主进程。`MpApi` 新增 `getHotkeyBlock` / `setHotkeyBlock`，入参过 zod 校验，返回整理后的名单，设置页拿它刷新文本框。
- **界面：** 设置页「呼出热键」下面加一个多行文本框，一行一个程序名，失焦保存，旁边灰字提示去任务管理器「详细信息」页签找文件名。

## 放弃的方案

- **全屏自动判断：** 不用维护名单，但看全屏视频、放 PPT 时也会被拦住，行为不如名单可预期。以后真需要，可以在同一个守卫里再加一条判断。
- **每次触发时临时起 PowerShell 查前台：** 不用加依赖，但启动一次要几百毫秒，呼出会明显变慢。
- **从「正在运行的程序」里选的选择器：** 要多写进程枚举的代码，而文件名在任务管理器里一眼能看到，等真觉得麻烦再加。
- **在热键钩子里直接拦（`hotkey.ts` 里判断）：** 钩子只管「检测到了什么按键」，不知道窗口当前是显示还是隐藏，拦了也分不清是呼出还是收起；放在 `app.ts` 的呼出分支里最准。
- **macOS 实现：** 场景是 Windows 上玩游戏，Mac 要另写一套查询方式，`foregroundExeName()` 在非 Windows 返回 `null` 即可，需要时再补。
- **被拦时给提示：** 见上，提示本身会盖到游戏上。
