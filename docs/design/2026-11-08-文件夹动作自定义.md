# 文件夹动作自定义

## 目标

文件夹条目按 → 展开的子菜单，原来写死三项（在此打开终端 / opencode / Claude Code）。改成用户可以自己增、删、改。

## 方案

- **动作 = 名字 + 一条命令 + 自动关闭开关。** 执行方式与原来的 opencode / Claude Code 完全一样：在该文件夹里开一个应用内终端，把命令送进去。自动关闭复用终端命令条目已有的机制（命令成功后关终端，失败时留着看报错）。
- **子菜单第一项「在此打开终端」固定**，不可删、走多语言、不带命令。其余项来自用户的动作列表。
- **全局一份**，所有文件夹条目共用。配置在设置 → 快速启动，条目列表下方的「文件夹动作」；新增 / 编辑走弹窗，每行带编辑、删除按钮。
- **存储**：settings 表新增键 `folderActions`，值为 JSON 数组 `[{name, command, autoClose}]`。键不存在 = 用预置两项（opencode、Claude Code）；用户一保存就整份写入（删光存 `[]`，不会被预置顶回来）。库里的值被手改坏了，当作没存过，回落预置。
- **限制**：名字必填 ≤ 30 字；命令必填、单行、≤ 500 字；最多 10 个。主进程入口 zod 校验，弹窗里同口径提示。
- **终端标题**：自定义动作开出的终端叫「动作名 · 文件夹名」，「在此打开终端」只叫文件夹名。
- **接口**：`MpApi` 新增 `getFolderActions` / `setFolderActions`，返回整份列表。读写与预置放在新模块 `src/main/server/folderActions.ts`。
- **顺手清理**：`LauncherList.tsx` 里写死三项的右键菜单没人引用（规格也写了没有右键菜单），一并删除。

## 放弃的方案

- **每个文件夹单独配动作**：条目弹窗会变复杂，而原来的三项本来就是所有文件夹通用的。
- **路径替换符**（如 `{路径}`）：终端已经站在该文件夹里，`code .` 这类写法够用。实测在文件夹里敲 `code .`，VS Code 打开的就是该文件夹。遇到不认 `.` 的程序再加。
- **「调起外部程序但不开终端」另一种动作**：多一套执行路径；靠命令 + 自动关闭已能覆盖。
- **排序按钮、恢复默认按钮**：就两三行的小列表，不值得；想调顺序就删了重加。
- **行内直接编辑**：保存时机和校验提示都更乱，弹窗与条目编辑的习惯一致。
