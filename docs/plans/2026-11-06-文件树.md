## 三、主进程：读目录接口

- [x] `src/main/server/schemas.ts`：加 `listDirSchema = z.object({ workspaceId: z.number().int().positive(), dir: z.string().trim().min(1).max(1000) })`。
- [x] `src/main/server/workspaces.ts`：加一个按 id 取工作区文件夹的函数，找不到或文件夹为空串时返回 `undefined`。
- [x] 新文件 `src/main/server/fileTree.ts`（纯函数风格，注释写「为什么」）：
  - 范围校验：`dir` 解析成绝对路径后，用 `path.relative` 判断必须等于或位于工作区文件夹之内。只做字面检查，不跟随符号链接。
  - 用 `readdir(dir, { withFileTypes: true })` 读一层。符号链接再 `stat` 一次判断目标类型，失败当文件。
  - 返回 `{ name, path, isDir }[]`，`path` 在这里拼好。不排序，不过滤。
- [x] `src/main/server/api.ts`：
  - `MpApi` 加 `listDir(workspaceId: number, dir: string): Promise<ApiResult<{ entries: DirEntry[] }>>`，`DirEntry` 类型一并导出。
  - `apiHandlers` 实现：`guard` 校验入参 → 查工作区文件夹（没有则 `not-found`）→ 调 `fileTree.ts`。错误映射：目录不存在 `missing`，越界或入参不合法 `bad-request`，其余读失败 `failed`。
- [x] `src/renderer/src/api/client.ts`：加一行转发。三处只要漏一处，`pnpm typecheck` 会报错。

## 四、渲染端：小工具

- [x] 把 `App.tsx` 里 `openInTerminal(item, command)` 拆成两层：新函数只吃「文件夹路径 + 可选命令」，原函数改成调用它。保持原有行为不变（标签名截断、`launch.missing` 提示）。
- [x] `src/renderer/src/lib/fileIcon.ts`：按文件名或文件夹名返回图标。
  - 用 `material-icon-theme` 的映射表匹配：先文件名，再扩展名（取最长匹配），文件夹先文件夹名，展开状态用展开款。匹配不上用默认文件或文件夹图标。
  - 先实测两种打包方式（图标文件懒加载 vs 整包图标数据），选更简单的，不要两种都做。同时量一下对打包体积的影响，结果记在设计文档的风险一节。
- [x] 排序函数：目录在前，文件在后，各自 `localeCompare("zh-Hans-CN", { sensitivity: "base" })`。放在 `fileIcon.ts` 旁边的小文件里，别塞进组件。

## 五、渲染端：面板组件

新文件 `src/renderer/src/components/FileTreePanel.tsx`，常驻在 `App` 里（不是挂在 Sheet 内部，否则关闭时状态全丢）。

- [x] 对外：`open`、`onOpenChange`、当前工作区 id 与文件夹、入口按钮的 ref（用来放过外点）、几个回调（打开路径、在此开终端、修改文件夹）。
- [x] 内部状态：按工作区 id 记展开列表（`Record<number, string[]>`，只在内存）；当前的根节点数据；刷新计数（做 `key`）。
- [x] 打开或点刷新时：从根开始逐层重读，把根和展开列表里的目录读出来拼成嵌套 `children` 的节点，读不到的展开目录从列表里去掉。
- [x] 展开新目录走 Tree 的 `loadChildren`，调用 `api.listDir` 后排序、转节点（图标、`hasChildren`）。
- [x] 外壳：`<Sheet modal={false}>` + `SheetContent`（`side="left"`、`showCloseButton={false}`），用 `className` 覆盖成「工具栏下沿起、侧栏右侧起、宽 320px」。`onInteractOutside` 里放过入口按钮。位置取值写成能一眼看懂的常量，样式细节留给后面调。
- [x] 标题栏：文件夹名 + 刷新 + 关闭两个图标按钮。
