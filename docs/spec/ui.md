# 界面与交互规格

长期规格，描述界面现在应该是什么样、为什么这样定。改界面行为时在同一次改动里更新这里；工作规则和命令见 [AGENTS.md](../../AGENTS.md)，内置工具见 [TOOL_SPEC.md](../../src/renderer/src/tools/TOOL_SPEC.md)。

主结构：顶栏（品牌、居中的搜索框、常驻按钮）+ 工具区。没有侧栏、没有标签条；窗口默认收成只剩顶栏的一条，有工具或终端在显示时才展开。

## 视觉与主题

- 界面为 GaN.UI 中性灰体系：来源仓库 `D:\MyCode\GaN.UI`，源码基线 v1.5.4（提交 `0edf835`），组件复制于 `src/renderer/src/components/ui/`，令牌与材质全在 `src/renderer/src/index.css`。
- 深浅双主题：深色默认（冷调石墨），浅色为「薄雾」（淡蓝灰底，色系经上游承自 Darwin 取色）。强调色：深 `#0a84ff` / 浅 `#4f46e5`。
- 字体：Outfit（可变）+ IBM Plex Mono，woff2 内嵌于 `src/renderer/src/assets/fonts/`。**不引入 MiSans，不引入 Geist。**
- 主题唯一权威来源是 settings 表 `theme` 键（dark/light）：
  - 主进程开窗前直读，定窗口 `backgroundColor`。
  - 渲染端 `index.html` 内联脚本经 preload 的 sendSync 同步桥（`getThemeSync`）在首帧前给 `<html>` 套 `.dark` 类。
  - 切换入口只有设置里的分段控件（顶栏没有主题按钮），即点即换，并经 `mp:set-theme` 通知主进程更新窗口外观。

## 窗口与顶栏

- 启动链上任何一步出错（开库、建表、迁移等）都弹错误框显示原因并退出，不留看不见的后台进程。
- 窗口**无边框**（`frame:false`），窗口边缘圆角与描边全归 OS，不自画。
- 拖拽区覆盖整个顶栏的品牌和空白区域（搜索框两侧都能拖）；搜索框、按钮和弹出内容保留 `app-no-drag`，才能正常接收输入事件。
- 顶栏高 48px，所有元素竖向居中。左槽品牌，**搜索框在中槽、水平居中**（左右槽定宽 140px 且相等，中槽吃满剩下的宽度，就落在顶栏正中），右槽依次是：收起（工具区展开时才有）、钉住、置顶、设置。没有工具菜单（用户决策，2026-11）：切换和关闭工具、终端都在搜索框的 `/` 列表里，见「搜索框」。
- **品牌**：名称走 i18n `app.brand`，中英文都是 `Knock`，上下叠两行（11px 字、12px 行高，两行合计 24px，放得进 48px 顶栏）。
- **搜索框**：32px 高，**宽度没有上限**（用户决策）：窗口拖多宽它就多宽，最窄 260px（窗口最小宽度 840 时远不会碰到）。下拉面板不跟搜索框同宽，铺满整个窗口宽度，见「搜索框」。
- 搜索候选收全部快捷启动条目；搜索框规则见下面「搜索框」。
- 钉住：失焦不自动隐藏，双击 Ctrl 不再收起，跨重启保持。按钮图标固定为图钉，不随状态换成划线款，是否钉住只靠按钮按下变色表示（提示文字仍在「钉住」和「取消钉住」间切换）。
- 置顶：钉住下的子状态，仅本次运行有效；未钉住时置顶按钮禁用。图标是「横线在上、箭头向上」（lucide 的 `ArrowUpToLine`）。

## 窗口形态

窗口无边框、不透明，「只有顶栏」只能靠窗口自己变矮实现。窗口有两种形态，渲染端经 `mp:set-layout` 把「展开与否」和「收起时临时需要的高度」报给主进程，主进程在 `app.ts` 的 `applyLayout` 里改窗口高度。

- **展开**：有工具或终端在显示（断线提示也算）。高度取上次展开时的高度（默认 1180×760，最小 840×520），用户拖过就记住。
- **收成一条**：什么都不显示时窗口只有顶栏那么高（`TITLEBAR_HEIGHT` = 48，主进程与渲染端 `lib/windowRoom.ts` 各有一份，要一起改）。竖向不能拖，宽度仍可拖。
- **宽度**两种形态共用；存库的 `height` 只是展开时的高度（见 data.md）。
- **临时撑开**：收成一条时，搜索下拉、设置/条目/确认弹窗、报错提示都放不下，它们各自登记「我需要窗口至少这么高」（`lib/windowRoom.ts` 的 `useWindowRoom`），窗口取这些需求和顶栏高度里最大的，东西消失就缩回去。搜索下拉登记的是固定的 48 + 480 = 528px，不随行数变。已展开时登记不起作用：弹窗和提示照旧悬浮在工具区上面；搜索下拉不悬浮，改为整块盖住工具区，见「搜索框」。
  - 窗口往下长，快碰到屏幕底边时整体往上挪（缩回去不挪回）。缩放没有动画。
- 窗口不能最大化（`maximizable: false`）：高度由内容决定，最大化与这套形态冲突。
- 收起按钮、关掉正在显示的工具、正在显示的终端里 shell 退出，窗口都直接收成一条，不自动切到别的。


## 搜索框

规则对所有工具一样，不是便签专属（实现在 `components/SearchBox.tsx`）。

**下拉面板不是悬浮层**（用户决策）：它是窗口里的一块正常内容，位置在顶栏正下方，铺满窗口宽度，没有边框、阴影和入场动画，底色同窗口。实现上经 portal 画进 App 的 `<main>`（工具区），状态仍都在 SearchBox。

- **窗口收成一条时**：面板一出现，窗口就长到 48 + 480 = 528px，面板高度固定 480px，行不够多时下面留空白、行太多就在面板里滚动，打字筛选时窗口不会跟着一伸一缩。
- **窗口已展开时**：窗口大小不变，面板整块盖住工具区（工具区高度是多少面板就多高）。后面的工具和终端都不卸载、尺寸不变，终端不会被重排，面板关掉原样露出来。
- **怎么关**：Esc；输入框失焦；鼠标点面板里没有行的空白处（等于让搜索框失焦，输入的文字保留，点回搜索框又弹出来）。点行、拖滚动条不会误关。
- 键盘高亮滚动只动面板自己的滚动位置，不用 `scrollIntoView`：它会连祖先一起滚，窗口刚从一条撑开的瞬间，根容器会被滚走、顶栏就看不见了。

下拉分三块，各答一件事：

| 区 | 回答什么 | 内容 | 选中后 |
| --- | --- | --- | --- |
| 命中区 | 我想找什么 | 匹配的快捷启动条目 + **所有**匹配的内置工具（名称、id、别名、描述的包含匹配）+ **所有**匹配的 AI 专家（名称，不论是否勾了推荐）。条目标题、工具名称与别名、专家名称还认拼音；条目在前、工具居中、专家在后，最多 9 行 | 只打开，不带字 |
| 推荐区 | 这段字交给谁 | 吃文本的工具 + 勾了推荐的专家，恒在 | 带入文字 |
| 路径区 | 输入像本地绝对路径且存在时 | 文件：打开文件 + 前往所在目录；文件夹：前往 | 执行动作 |

- **条目怎么匹配**：所有条目按标题匹配；**只有目标是本机文件夹的条目，目标路径也参与匹配**（用路径找文件夹）。网址、应用、命令、文件的目标一律不参与，否则打 `com`、`exe` 之类会命中一大片。「是文件夹」沿用 `dirIds` 的运行时判定，判定结果回来之前，文件夹条目只按标题命中。
- **拼音匹配**（`lib/pinyinMatch.ts` 的 `matchText`，用 pinyin-pro；「选快捷方式」弹窗的名称匹配共用它，该弹窗的目标路径仍只做字面匹配）：
  - **对谁生效**：条目标题、工具名称、工具别名、专家名称（专家只有名称可匹配）。工具 id、工具描述（整句话，首字母一打命中一大片）、文件夹路径只做字面匹配。字面包含永远算，拼音是多出来的一条命中路径。
  - **怎么写都行**：全拼、首字母、混拼（`weixin` / `wx` / `wxin` 都命中「微信」）；可以从中间的字开始，但要连续；查询里的空格忽略，标题里的空格也会被跳过；多音字的各个读音都算（`yinle`、`yinyue` 都命中「音乐」）。
  - **只认字母和空格**，且**至少 2 个字母**才走拼音（1 个字母如 `w` 会命中所有首字母是 w 的条目）。少于 2 个字母时字面匹配照旧：单个字母、单个汉字仍按包含匹配。带数字、符号的查询也只做字面匹配。
  - **只有汉字走拼音**：标题里没有汉字时只做字面匹配；英文部分不做缩写、不跳字（`vsc` 不命中 Visual Studio Code，`tl` 不命中 Translate）。
  - **只对手打的字生效**：带着剪贴板素材（chip）时，匹配源是复制来的数据，只做字面匹配。
  - 命中区的顺序和 9 行上限不变：字面命中与拼音命中混在一起，仍按固定顺序排，不做相关度排序。
- **带入内容**：有复制内容（chip）带复制内容，否则带打的字。只有推荐区的行带字，命中区的行（包括便签、translate 这类吃文本的工具）只打开。命中区里的专家行只打开 AI 工具并切到该专家：单轮专家不自动发送，多轮专家聚焦空输入框。
- **同一个工具、同一个专家都可能出现两次**：命中区一行（只打开）、推荐区一行（带字），按想不想带字选。没勾推荐的专家只会出现在命中区，只有打出名字（含拼音）时才冒出来。`/` 列表不含专家，专家的管理和切换留在 AI 工具里。
- **推荐区永远显示**：基础顺序固定为便签、json、qrcode、files、translate，勾了推荐的专家排在后面。内容是链接或 JSON 时，qrcode 或 json 临时排到第一，其余相对顺序不变（打 JSON 时是 json、便签、qrcode、files、translate）。便签在 `TOOLS` 数组里排在最后，`/` 列表里工具段的顺序（按 `TOOLS` 数组）不受影响，推荐区的顺序在 SearchBox 里单独定。
- **默认高亮与 Enter**：
  - 纯手打：路径区和命中区在上、推荐区沉底，Enter 落第一个路径/命中行；↓ 走到底进推荐区。
  - 手打但路径区、命中区都没东西：显示「（无匹配）」，**不预选任何行，Enter 什么都不做**，要带字先按 ↓ 选推荐行。手打的字不会悄悄进便签。
  - 有复制内容（chip）：从上到下是路径区、推荐区、命中区，高亮第一行。复制的不是路径时第一行就是推荐区第一行，Enter 直接注入，「复制 → 呼出 → Enter」的素材流不变；复制的是存在的本地路径时，第一行是路径区的「打开文件」或「前往文件夹」，Enter 直接打开，要带进便签等工具就按 ↓ 选推荐行。
- **路径区恒在最上**：不管是手打还是复制的内容，只要是存在的本地路径，路径区就排在所有区的最前面。
- 搜索框里粘贴图片不做处理。
- **输入为空时没有下拉。** 按 `/` 弹出全部列表（面板内可滚动），从上到下三段，每段有小标题：
  - **运行中**：已打开的工具和每个终端会话，**有东西开着才出现**。选中 = 切过去，正在显示的那行用强调色。高亮（含鼠标悬停）时行尾出现 ×，也可按 Delete 关闭；Delete 只对这一段生效，条目和没打开的工具按 Delete 什么都不做，不会误删条目。关工具直接关、列表留着；关终端先弹确认（会话一关，里面正在跑的程序就没了），列表随之收起。
  - **快速启动**：全部条目（顺序同下面的固定规则），没有条目时标题下提示去设置添加。
  - **工具**：没打开的工具（按 `TOOLS` 数组顺序），已打开的只在运行中段出现、不重复。「终端」一行永远在，选中 = 新开一个会话。选工具只打开，不带字。
  - 默认高亮第一个条目：`/` 之后 Enter 开条目的习惯不变，按 ↑ 才走到运行中；没有条目时不预选。
  - 焦点在别处的输入框（含终端）里 `/` 照常打字；在本搜索框里，只有没有 chip、没有字时 `/` 才弹列表，否则就是普通字符。
  - 搜索框右边的「/」键帽可以点，效果同按下 `/`。有字或 chip 时按键只是普通字符，点键帽则是明确要列表，所以先清掉字和 chip 再弹出。
  - ↑↓ 选、Enter 打开、Esc 关闭列表、点面板空白处也关闭；打字后变回搜索。呼出时带着剪贴板素材，下拉照旧自动弹出：窗口已展开时它会整块盖住正在用的工具，Enter 注入后马上收起，不想用就按 Esc 清掉素材。
  - 这是没有侧栏、没有工具菜单之后，浏览条目、切换和关闭工具与终端的唯一入口。**打字搜索的结果不显示运行状态，也不搜终端会话**：命中的工具选中就是打开，已经开着的就切过去，终端每次新开一个。
- **文件夹条目的子菜单**（`/` 列表和搜索结果里都有）：行尾有个淡淡的 ▸。按 `→`（光标在文字末尾时）在这一行**下面行内展开**子菜单（缩进到标题那一列，不是悬浮卡片）：第一行固定是「在此打开终端」，后面是用户自己的**文件夹动作**（见下面「文件夹动作」），每行显示成「在此打开 ＜动作名＞」，默认带 opencode 和 Claude Code 两项。↑↓ 选，Enter 执行，`←` 或 Esc 只收子菜单。鼠标点 ▸ 展开，再点一次收回。子菜单开着时，方向键和 Enter 只管子菜单，鼠标路过别的行不会把高亮挪走。Enter 在行上仍是打开文件夹。没有右键菜单。

## 文件夹动作

文件夹条目按 → 展开的子菜单里，「在此打开终端」之后的那几行，用户可以自己增删改。**全局一份**，所有文件夹条目共用，不能给单个文件夹单独配。

- **一个动作 = 名称 + 命令 + 自动关闭开关。** 执行方式：在该文件夹里开一个应用内终端，把命令作为会话首条命令送进去。命令里没有路径替换符，终端已经站在那个文件夹里，要用路径写 `.`（比如 `code .` 在 VS Code 里打开该文件夹）。自动关闭与终端命令条目是同一套机制：命令成功后关掉终端，失败时留着看报错。
- **限制**：名称必填、≤ 30 字；命令必填、单行、≤ 500 字；最多 10 个。命令输入框是单行的，本身挡掉换行；全是空白算没填，保存按钮灰着。到 10 个后「新增动作」按钮灰掉。
- **预置**：从来没保存过时是 opencode（命令 `opencode`）和 Claude Code（命令 `claude`）两项，可改可删；一保存就整份写入，删光就是空（不会被预置顶回来）。
- **终端名**：动作开出的终端叫「动作名 · 文件夹名」（文件夹名按终端名上限截断），「在此打开终端」只叫文件夹名。
- **不做**：排序、恢复默认、给单个文件夹单独配。想调顺序就删了重加。
- 编辑入口在设置 → 快速启动分节的下半段「文件夹动作」：一行一个（名称、命令、编辑和删除；删除不二次确认），顶部「＋新增动作」，新增和编辑弹出 `FolderActionDialog`。存储见 [data.md](data.md) 的 `folderActions`。

## 快速启动条目

没有侧栏。条目只在搜索框里找（输入，或按 `/` 列出全部），新增、编辑、删除只在设置的「快速启动」分节里（列表一行一条：图标、标题、目标，行尾编辑和删除，顶部「＋新增条目」；标题和目标过长都显示省略号（目标悬停看全文），设置页不出现横向滚动条；条目弹窗和删除确认框叠在设置页上面）。

- **图标**（`lib/kindIcon.tsx`，搜索候选和设置列表共用）：取自 Material Icon Theme，两种来源：
  - **手选**：条目弹窗里的「图标」一行，点开「选择图标」子对话框（`IconPickerDialog`）：搜索框 + 全部可选图标的网格（915 个，不含浅色款和文件夹展开款），悬停看名字，点一个即选中，底部「恢复自动」。搜索匹配图标名，也匹配映射到它的扩展名 / 文件名 / 文件夹名（搜 `md` 找到 markdown；用「恰好等于」，免得冒出一大片）。选中的图标名存进 `items.icon`。
  - **自动**（没手选，`icon` 为空）：网页收藏 = `http`（地球），应用 = `exe`（窗口），终端命令 = `console`（终端），这三类各用固定一张；文件类按目标的文件名 / 扩展名匹配，目标是本机目录（`dirIds`）则按文件夹名匹配。目录判定结果回来之前，文件夹条目先按文件显示。
  - 库里的图标名图标包里没有时（旧版遗留、包升级删了）一律按自动显示；编辑弹窗也把它回填成「自动」，保存一次就清掉。
  - 浅色主题用专为浅底画的款式（手选的也一样：有 `<名>_light` 就换），所以搜索框、设置列表和条目弹窗都要传 `light`。
- **顺序固定**：网页收藏 → 应用 → 文件/文件夹 → 终端命令，同类型按标题升序（中文按拼音、忽略大小写）。规则只在 `lib/itemOrder.ts` 定义，搜索候选、`/` 列表与设置列表共用，新增条目按规则归位而非追加末尾。
- **打开**：Enter 或单击即启动（500ms 同条目防抖，吞掉连点与双击）。网页收藏交给系统默认浏览器并藏窗口（钉住时不藏）；应用、文件启动成功后同样藏窗口；终端命令在工具区新开一个终端并显示，不藏窗口。
- 条目为空时（冷启动）没有任何引导占位：`/` 列表里提示「到设置的快速启动里添加」。

## 工具区

`components/ToolArea.tsx`：同一时间只显示一个工具或终端，其余活着的只是 `hidden`（`display:none`）。**没有标签条，没有工具首页。** 活着的工具、终端会话和当前显示项都归 `App.tsx` 持有（开工具、起终端、shell 退出、后台超时都在那里），`ToolArea` 只负责画。

- **保活与卸载**：没显示的只是 `hidden`，草稿、终端回滚缓冲都留着；关掉才卸载，工具回到初始态，终端会话结束。**每次启动从空开始，不还原（用户决策，勿加）。**
- **打开规则**：除终端外每个工具只有一个实例，已活着再选只是切过去；终端每次选工具段里的「终端」一行都新开一个会话。打开即显示。关掉正在显示的那个，窗口收成一条，不自动切到别的。
- **切换与关闭**：工具和终端的唯一入口是搜索框的 `/` 列表（`components/SearchBox.tsx`，见「搜索框」）：「运行中」段切换和关闭，「工具」段打开。顶栏不显示当前是哪个工具或终端，也没有别的东西顶替：工具内容自己说明是谁，要切换就去 `/` 列表，正在显示的那行是强调色。终端会话的名字跟着 shell 标题走。
- **收起按钮**：顶栏上「收起」（向上的箭头），只在展开时出现。窗口缩成一条，工具和终端继续活着。
- **后台自动关闭工具**：窗口藏起来（`mp:window-visible` 事件）满「存活时间」（设置里 5 / 10 / 30 / 60 分钟 / 不自动关闭，默认 10 分钟，存 `toolIdleMinutes`），一次关掉所有非终端工具。
  - 从窗口藏起来那一刻起算，到点一起关，中途窗口再显示就取消计时；窗口可见（含钉住）时不计时。
  - **终端永不自动关闭**，只有 shell 自己退出、你手动关、或应用退出才结束。
  - 存活时间在每次隐藏时现读，设置里改了从下一次隐藏起生效。
  - 不给没保存的内容加豁免：便签草稿会丢，图库正在进行的网址抓取会中断；AI 会话在内存仓库里，不受影响。
- **终端名**：初始是会话标签（命令条目取标题，文件夹条目取文件夹名，文件夹动作取「动作名 · 文件夹名」），之后跟着 shell 用 OSC 0/2 设的标题走，后到的标题会覆盖前面的名字。标题长度上限与清洗规则在 `lib/termTitle.ts`。没有手动改名。
- **工具内「打开设置」**：分节跟随当前显示的工具（translate、ai 有缺配置态），其余落回翻译分节。
- 终端切回前台时重新 fit 并聚焦（`TermPanel` 的 `active`）。隐藏时容器是 0 尺寸，fit 无意义，所以只在可见时做。

## 终端会话

- 终端工具入口 id 为 `terminal`（属于 ToolId），每个终端会话使用独立数字 id，在 `/` 列表的「运行中」段里与已打开的工具并列切换。
- **工作目录**：终端命令条目填了工作目录就用填的，留空走主目录；终端工具新开的会话走主目录；文件夹条目子菜单里的「在此打开终端」和各文件夹动作用文件夹自己。
- **运行 ps1 脚本**：条目弹窗里类型选「终端命令」时，目标栏旁多一个「选择脚本…」按钮（仅 Windows），对话框只放行 `.ps1`，起始目录用系统默认位置。选中后一次填三处：
  - 命令栏：`pwsh -NoProfile -ExecutionPolicy Bypass -File "脚本路径"`；设置页查到本机没有 pwsh 就写成 `powershell`（Windows 自带的 5.1，读无 BOM 的 UTF-8 脚本会乱码，所以排在后面）。写成子进程调用而不是 `& 脚本`，是为了不管终端程序选 cmd 还是 PowerShell 都能跑，执行策略只对这一次放行。
  - 工作目录栏：脚本所在目录，**每次选都覆盖**（换脚本不留旧目录）；填完仍可手改。没走按钮、手敲的命令不自动带目录，仍按上面的规则。
  - 标题栏：为空时用脚本文件名（去扩展名）。
  - 命令照常敲进新开的终端，脚本跑完终端默认保留（shell 没退出），由用户自己关；想自动关见下一条「自动关闭」。「应用」「文件」类型和搜索框里的 `.ps1` 路径不变，仍用系统默认方式打开。
- **自动关闭**（仅终端命令，条目弹窗里的开关，默认关）：勾上后，命令**成功**结束就自动关掉那个终端；命令失败则终端保留，方便看报错。
  - **做法**：命令后面追加「成功才退出 shell」，PowerShell 是 `; if ($?) { exit }`，cmd 和各类 POSIX shell 是 ` && exit`。PowerShell 5.1 没有 `&&`，所以不能一律写它。
  - **追加什么由主进程给**：`ptySpawn` 的返回里带 `exitSuffix`（`pty.ts` 的 `exitOnSuccess`）。设置里选「自动」时实际用哪个 shell 只有主进程知道，渲染端不猜。命令仍由渲染端在 pty 起来后写入，没挪到主进程，免得改变写入时序。
  - **怎么关**：shell 一退出，`App.tsx` 里已有的 pty `exit` 事件处理就会关掉这个终端（`closeTerm` 里 dispose xterm），没有另外的关闭机制。
  - 弹窗里这一行只在类型为「终端命令」时显示，其他类型一律存 0；编辑时按存的值回填。已实测 PowerShell 7、Windows PowerShell 5.1、cmd 三种终端程序。macOS 的 zsh / bash 走 `&& exit`，未实测。
- **环境变量**：新建会话将 `TERM` 设为 `xterm-256color`、`COLORTERM` 设为 `truecolor`，并清除继承的 `NO_COLOR`，避免启动环境禁用彩色输出。
- **xterm 实例归 `termStore.ts`**，与组件生命周期解耦：组件重挂（开发态 StrictMode 会把 effect 跑两遍）只重挂 DOM，不丢回滚缓冲；会话结束才 dispose；实例未就绪前的 pty 输出由它缓冲回放。
- 主题切换经 html 类监听热更新 xterm 配色，不重建进程，不清缓冲。

## 设置

- 分节内容随弹窗打开才挂载。剪贴板时限、翻译密钥、AI 模型由各分节挂载时自己读、提交时自己写，失败 `toast.error`，`App` 不持有它们。
- 界面主题、终端、字体和工具别名启动就要用，留在 `App`。
- **快速启动分节**（`LauncherSection`）：条目的唯一编辑入口，见上面「快速启动条目」。条目列表、新增/编辑/删除都由 App 持有，条目弹窗叠在设置页上面，所以 App 里设置页和条目弹窗是两个独立状态；下半段的文件夹动作列表由 App 持有，保存走 App，弹窗由本分节自己持有。
- **后台自动关闭工具**：基础设置里的下拉，即选即存，只有这里读写（App 每次窗口隐藏时现读），见「工具区」。
- AI 模型是 AI 工具和设置页共用的，放在共享 store `lib/aiModels.ts`：在设置里保存后，已打开的 AI 工具立刻生效，不用重开。
- **呼出热键的屏蔽名单**（只在 Windows 显示）：基础设置里「呼出热键」下方的多行文本框，一行一个程序文件名，失焦保存。名单里的程序在最前面时（典型是全屏游戏），双击修饰键和组合键都不呼出窗口，被拦时没有任何提示（提示会再盖到游戏上）。
  - 只拦「呼出」：窗口已显示时按热键照常收起；托盘点击、二次启动唤起不受影响（`app.ts` 里托盘走 `toggleWindow`，热键走 `toggleByHotkey`）。
  - 保存时整理成小写、补 `.exe`、去重，粘贴整条路径只留文件名；整理后的结果回填文本框。
  - 前台程序用 `koffi` 查（`server/foreground.ts`，Windows 专用）。查不到（`koffi` 不可用、受保护进程不让查）当作没命中，照常呼出，保证热键不会因一次查询失败而失灵。名单为空时不去查。

## 图库

- **网格**：整个网格只有一个右键菜单，点击和右键都在容器上按格子的 `data-index` 处理，空白处右键不弹菜单。格子是 `memo` 组件，勾选一张只重渲染那一格。没有上虚拟列表，真到上万张再上。
- **缩略图**：`mpimg://thumb/<id>` 回 404 时先显示占位，排队交给 Worker 生成（长边 320，不放大），同时最多 2 张，同一张只生成一次。存盘后带 `?v=1` 重新请求，绕开浏览器对失败结果的缓存。生成失败显示名字兜底块。
- **查看器**：删图只在本地移除这一张并刷新侧栏计数，不重置列表，也不滚回顶部。
- **从网址导入**：
  - 首页先探测一次 `content-type`（`galleryProbeUrl`），是图片就当单张候选。探测失败不算错，其余都走隐藏窗口渲染收集，没有静态解析。
  - 隐藏窗口翻页间复用，空闲 30 秒或会话清场（`galleryCollectReset`）时销毁，失败或超时后也销毁。
  - 每页总时限 15 秒，只等 `dom-ready`，到点就用已加载的 DOM 收集，所以图多的慢页面不算失败。
  - 首页渲染失败才报错；翻到后面的页失败时停止翻页，已收集到的候选照常呈现。
  - 抓取全部走抓取分区的 `session.fetch`，和隐藏窗口共用 cookie 与代理。`ProxyEnable=1` 时自动走系统代理；直连失败时读注册表 `ProxyServer` 试用一次，能通就固定下来，都不通就还原。超时覆盖到响应体读完，体积上限边读边判断。
  - `session.fetch` 的三个坑：`res.url` 恒为空串；https 的 referer 请求 http 目标时必须传 `referrerPolicy: "unsafe-url"`；`reader.cancel()` 不断开连接，提前结束要用 `AbortController.abort()`。
  - 隐藏窗口注入采集脚本要用 `mainFrame.executeJavaScript`，`webContents.executeJavaScript` 会等页面加载完。

## AI 助手

- 增量在 `aiSessions` 里攒 80ms 再提交。用定时器而不用 `requestAnimationFrame`：窗口藏到托盘时动画帧不触发。
- 消息行是 `memo` 组件，流式时只重渲染末条，历史消息不会重新解析 Markdown。
- 终结、停止、清空、重试、回滚、删专家之前都先写入积压的文字，保证不丢、不串。

## 便签

工具 id `notes`，中文「便签」，英文 `notes`。记一闪而过的想法和临时数据，全局一份，搜索框搜不到便签内容。入口只有搜索框（打字，或 `/` 列表），没有独立热键。

- **一条便签** = 一段文字 + 多张图片，可以只有其中一种，不能全空。文字原样显示（不渲染 Markdown），图片排在文字下方。
- **输入区**（顶部新建和条目编辑共用 `tools/notes/NoteInput.tsx`）：
  - 顶部新建的输入区单独成一条浅色横带，带底边线和轻阴影，与下方列表明显分隔；输入框本身比面板底色深，不加横带会和列表混在一起。
  - 从任何入口打开或切回便签时焦点进入输入框，高度随内容增长。
  - Ctrl+回车保存（macOS 上 Cmd+回车也行），回车换行；输入法选词时的按键不触发保存。保存后清空，焦点留在输入框；文字全是空白且没有图片时不保存。
  - 没保存的草稿（含图片）切到别的工具时还在，关掉（含后台超时自动关）就丢。
  - 加图三种方式：焦点在输入框时 Ctrl+V、把文件拖到便签页任意位置、点按钮选文件（可多选）。保存前图片显示为小图，每张带 ×。
  - 拖到编辑中条目的输入区上，图片加到那一条；拖到别处加到顶部输入区。
  - 剪贴板文字非空时走默认粘贴（从 Excel、Word 复制只取文字）；否则取文件，非图片提示格式不支持。所有粘贴都 `stopPropagation`，否则 ScanTool 挂在 `window` 上的 paste 监听也会收到。
  - 粘贴、拖拽、选文件都统一成 `File`，保存时转成字节发给主进程。不用 `clipboard.readImage`：它会把所有图片转成 PNG，也拿不到复制的文件。
  - 支持 jpg、png、gif、webp、bmp，单张不超过 20MB，一条最多 20 张，单条文字不超过 10 万字；超出或格式不支持时 toast 提示。上限常量在 `tools/notes/limits.ts`，与主进程 `schemas.ts` 的 `NOTE_*` 手工保持一致。
- **搜索框带入**：选便签后回车，便签打开、内容进入输入框、焦点进入输入框，**不自动保存（用户决策，勿改）**；已有草稿时换行追加（其他工具仍覆盖）。
- **列表**：按创建时间倒序，每条依次显示时间（`11-05 14:32`）、文字、图片。不做置顶、标签、颜色。文字等宽、可选中，超过 10 行折叠可展开。图片限高 120px 显示原图（不生成缩略图），点击用系统默认程序打开，没有应用内查看器。
- **悬停按钮**：整条有复制文字（没有文字时不显示）、编辑、删除；每张图有复制图片（经 canvas 转 PNG，GIF 只得到静态图）。
- **编辑**：点编辑后这一条变成和顶部一样的输入区，能改文字、删图、加图。Ctrl+回车或保存按钮保存，Esc 取消，点别处不自动保存（点 × 或选文件都会让输入框失焦，容易误存），保存后位置不变，全空时不让保存。多条可以同时处于编辑状态。
- **删除**：整条立刻消失，不弹确认，toast 上 5 秒内可撤销。界面先隐藏，5 秒后才真正调 `noteDelete`；组件卸载（关掉便签工具）时立刻执行还没到时间的删除；应用在这 5 秒内退出时便签会留下，可以接受。不做一键清空，不自动过期。
- **不做**：独立热键、搜索框粘贴图片、便签内查找、应用内看图、缩略图、图片去重。
